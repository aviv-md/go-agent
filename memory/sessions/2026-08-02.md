## Milestone: Task 7 done — types carry tools, provider maps both directions

**Decided / implemented** (all code by the human; assistant coached)

- `Message` became an interface hierarchy (`Message` / `AssistantMessage` / `ToolMessage`) over one unexported `message` struct. Constructors (`NewUserMessage` / `NewSystemMessage` / `NewAssistantMessage` / `NewToolMessage` / `NewToolCall`) are the only door; validation lives in them. Go's answer to missing sum types: interface + role discriminator + type switch.
- Known trade-off: one concrete struct implements all interfaces, so raw type assertions always succeed — the hierarchy is documentation, not a partition. Discriminate by `Role()`, never by assertion.
- `Response` type deleted; `Model.Prompt` returns `AssistantMessage` directly.
- Provider fan-out: one `Message` → `[]ResponseInputItemUnionParam`, switched on *our* role. Assistant = 0-or-1 text item (guard: no empty text items) + N `function_call` items, always. Tool = one `function_call_output` (callID + content), always — even empty output, the API demands every call answered.
- Response side: walk `resp.Output`, keep `function_call` items; `CallID` (not `ID`) is the pairing id; `arguments` JSON string ↔ `map[string]any` both directions via `encoding/json`; unmarshal failure returns an error — never panic on untrusted model output.
- `Role = string` alias became a distinct `Role string` type with typed constants.
- Full suite green; `openai_test.go` role test now guards the retired `RoleTool` seam instead of documenting the bug.

**Scars for Task 13 (presentation ore)**

- Same-type positional params: passed `(content, callID)` to a helper wanting `(callID, output)` — compiles clean, explodes live. SDK param helpers order fields alphabetically.
- "Guard the rendering, never the record": an empty-content guard placed in the agent loop dropped the Action from the transcript → dangling Observation. The guard belongs in the provider's mapper, scoped to the assistant text item only.
- SDK union types are fat structs with a `Type` string and comment guardrails — our constructor gate is genuinely better.

**Open for Task 8**

- How tool definitions travel to the provider: `Prompt` signature takes messages only; the request needs a tool menu. Constructor-time static menu vs per-call param — decides how thick `internal/tools` becomes (the architecture doc's open design note).
- What the one dumb tool is: boring + deterministic narrates best cold.
- `httptest` contract test deliberately left in extras backlog (night before the talk; live Task 11 smoke is the demo's validation).

**Next focus**

- Task 8: `internal/tools` thin slice — register + execute one dumb tool; answer the wiring question above.
